# Development Path

## Phase 0: Repository and provenance

### Outcomes

- archive research under `docs/handoff/`
- commit bootstrap files
- establish primary Codex thread
- record Build Week start point
- verify local toolchain

### Exit condition

A clean repository opens, documents resolve, and provenance is explicit.

## Phase 1: Domain model

### Outcomes

- strict TypeScript workspace
- runtime schemas
- serializable force, entity, profile, scalar, pair, threshold, dice, effect, coverage, and hole objects
- fixture loader
- schema tests

### Exit condition

Both proxy fixtures validate with zero protected names or copied prose.

## Phase 2: Exact projection engine

### Outcomes

- exact D6 enumeration
- threshold subset construction
- pair-strain functions
- clean attack-sequence projection
- exhaustive tests
- boundary and monotonicity property tests

### Exit condition

Every sample projection matches brute-force enumeration.

## Phase 3: Coverage and holes

### Outcomes

- pairwise profile matrix
- explicit capability function
- absolute-hole detector
- initial efficiency-hole detector
- counterfactual replacement search
- seeded fixtures with known expected holes

### Exit condition

Known holes appear and known counter-profiles close them.

## Phase 4: Visual language

### Outcomes

- list overview
- interactive matrix
- pair-detail panel
- threshold bands
- D6 sample-space cells
- effect distribution
- hole severity view
- before-and-after transition animation

### Exit condition

A new viewer understands one complete projection stack within thirty seconds.

## Phase 5: GPT-5.6 integration

### Outcomes

- constrained rule intermediate representation
- schema validation
- compilation retry and rejection paths
- explanation prompt with computed evidence only
- claim-to-evidence references
- evaluation fixtures

### Exit condition

Invalid rules fail safely, valid rules compile consistently, and explanations contain no unsupported numbers.

## Phase 6: Demo and submission hardening

### Outcomes

- polished default scenario
- deterministic seed
- local and deployed run instructions
- accessibility pass
- error states
- performance pass
- three-minute demo recording
- repository cleanup
- submission copy
- primary Codex Session ID from `/feedback`

### Exit condition

A judge can understand, run, and evaluate the project without author assistance.

## Post-hackathon Phase A: Post-game diagnosis

- event-log schema
- decision and variance separation
- breakpoint report
- minimal-intervention analysis
- regret under explicit policy assumptions

## Post-hackathon Phase B: Abstract list geometry expansion

- richer capability dimensions
- redundancy and fragility
- mission-conditioned holes
- archetype clustering
- sparse identifiable coordinates

## Post-hackathon Phase C: Board-state projection

- deployment as initial condition
- finite spatial grid
- reachability
- action funnels
- score envelopes
- stochastic trajectory families

## Phase ordering rule

No later phase may weaken exactness, provenance, or reproducibility established earlier.
